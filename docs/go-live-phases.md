# แผนทำงานทีละเฟส — 8 พฤศจิกายน 2026

ทำและรายงานแยกแต่ละเฟส ไม่ถือว่าเฟสผ่านจากการ build อย่างเดียว และไม่เปิดใช้งานเงินจริง/เผยแพร่ production ระหว่างเตรียมงาน

| เฟส | ผลส่งมอบ | เกณฑ์ผ่าน |
|---|---|---|
| 1 — ข้อมูลและหลายสาขา | migration รักษาข้อมูลเดิม, สิทธิ์สาขา, ราคา/สต็อกรายสาขา, ขาย/คืน/รายงาน/QR/realtime, cache/offline แยกสาขา | ข้ามร้าน/สาขาที่ไม่มีสิทธิ์ไม่ได้; ยอดสินค้าไม่เพิ่มจาก migration; ขายพร้อมกันไม่ติดลบ; คืนสต็อกเข้าสาขาเดิม; UI มือถือ/tablet ใช้เลือกสาขาและกำหนดสิทธิ์ได้ |
| 2 — บัญชีและตั้งร้าน | ยืนยันอีเมล กู้รหัสผ่าน คำเชิญทีม worker ส่งอีเมล; draft และ idempotency ของ onboarding | token ใช้ครั้งเดียว/หมดอายุ/จำกัดความถี่; กู้บัญชีเองได้; retry ไม่สร้างร้านซ้ำ; SMTP ล่มไม่ทำข้อมูลหาย |
| 3 — สมาชิกและเงิน | คงแพ็กเกจข้าม signup/login/setup, checkout/status, subscription lifecycle, webhook retry/reconcile, cancellation/receipt | จ่ายแล้วใช้บัญชีเดิมเองได้; ซ้ำ/สลับลำดับไม่เพิ่มสิทธิ์ซ้ำ; ต่ออายุ/ไม่สำเร็จ/ยกเลิก/คืนเงินทำงานตามเงื่อนไข |
| 4 — Production และการปฏิบัติการ | deployment/config validation, health/logs/alerts, backup/restore/rollback, bootstrap ไม่มี demo, ข้อเสนอขาย/นโยบาย/support/Enterprise | staging ติดตั้งซ้ำได้และกู้ backup ได้จริง; ตั้งค่าผู้ให้บริการและตรวจข้อความขายครบ; ยังไม่ deploy จนมีปลายทางและสิทธิ์ที่จำเป็น |
| 5 — ทดสอบจริงและ pilot | E2E ทั้งเส้นทาง, workload/concurrency, อุปกรณ์จริง, provider sandbox/live smoke, pilot และรายงาน go/no-go | ผ่านเกณฑ์ที่กำหนดด้วยหลักฐานจริง; แยกผลจำลอง/local/sandbox/live; ระบุ hardware/integration ที่ยังรอได้ตรงไปตรงมา |

สิ่งที่ต้องใช้ข้อมูลภายนอก: SMTP, บัญชี gateway และ keys, production hosting/DNS, เครื่องพิมพ์/อุปกรณ์จริง จะรายงานเป็น dependency ของเฟสนั้น ไม่อ้างว่าผ่านจาก mock tests

## ทิศทางเปิดบริการที่ปรับใหม่ — 10 พฤศจิกายน 2026

ผู้ใช้เลือกนำร่อง **5 ธุรกิจ ฟรี 30 วันก่อนเปิดขายเต็มรูปแบบ** จึงแยกงานต่อจากเฟส 3 เป็น [แผน implementation นำร่อง A–F](pilot-implementation-plan.md): A ฐานข้อมูล/สิทธิ์ → B สมัคร/หน้าเว็บ → C ฟีดแบ็ก/ดูแล → D production ขั้นต่ำ → E ทดลองจริง 30 วัน → F Stripe/เปิดขาย

งาน production ที่จำเป็นในเฟส 4 เดิมยังต้องผ่านก่อนร้านจริงเริ่มใช้ ส่วน Stripe Sandbox ของเฟส 3 ยังค้างและต้องผ่านก่อนเปิดเก็บเงิน แต่ไม่ขวางการเปิดนำร่องฟรี ขณะนี้เฟส A ผ่านการตรวจ local แล้วตามรายงานด้านล่าง ส่วน B–F และ deployment โครงการนำร่องยังรอดำเนินการ

## รายงานแต่ละเฟส

สถานะล่าสุด 11 พฤศจิกายน 2026: **เฟส 1–2 ผ่านใน local; เฟส 3 งานระบบ/local ผ่านแต่รอ Stripe Sandbox; Pilot A ผ่านใน local** — [รายงานเฟส 1](phases/phase-1.md), [รายงานเฟส 2](phases/phase-2.md), [รายงานเฟส 3](phases/phase-3.md), [รายงาน Pilot A](phases/pilot-a.md) ชุดทดสอบล่าสุด **66/66 ผ่าน** พร้อม typecheck/production build และยอดข้อมูลเดิมตรง baseline Campaign ยัง DRAFT, release ยัง LEGACY, ไม่มีคำเชิญ/ผู้เข้าร่วมจริง การตรวจมือถือ/tablet และ [SMTP จริง](phases/smtp-live.md) เป็นหลักฐานเฟสก่อน ไม่ได้ตรวจ UI หรือส่งอีเมลนำร่องจริงซ้ำใน A ผู้ใช้ยังไม่มีบัญชี Stripe จึงยังไม่ผ่านการจ่ายกับ provider และไม่พร้อม go-live งานต่อไปคือ Pilot B; การ restore backup/โหลด/อุปกรณ์จริงและ deployment production ยังอยู่ในเฟสที่กำหนด

ใช้รูปแบบ: สิ่งที่เปลี่ยน → ผลทดสอบ/หลักฐาน → ผลต่อข้อมูลเดิม → ข้อจำกัด/งานรอ → สถานะและเฟสถัดไป รายงานอยู่ใน `docs/phases/` และสรุปในแชตเมื่อจบเฟส

## เฟส 1: กติกาย้ายข้อมูล

- สำรองฐานข้อมูลก่อน migration ไม่ reset/reseed ฐานข้อมูลเดิม
- ยอดสินค้ารายชิ้นเดิมเป็นยอดรวมธุรกิจ ไม่มีหลักฐานแบ่งคลัง จึงย้ายทั้งหมดไปสาขาหลักเดิมเพียงครั้งเดียว สาขาอื่นเริ่ม 0 ห้ามคูณยอดเดิมทุกสาขา; เจ้าของต้องตรวจการกระจายสินค้าก่อนใช้งานหลายคลัง
- เจ้าของเข้าทุกสาขา พนักงานเดิมได้รับ grant ตามสิทธิ์เดิมที่เข้าทุกสาขาอยู่ก่อนแล้ว และมีหน้าปรับรายสาขา; พนักงานใหม่ต้องระบุสาขา ไม่ได้รับสิทธิ์สาขาที่สร้างเพิ่มโดยอัตโนมัติ
- รายละเอียดสินค้าเป็นแคตตาล็อกร่วม ราคา สถานะเปิดขาย และจำนวนคงเหลือแยกตามสาขา การแก้ยอดใช้เวอร์ชันเพื่อไม่ทับยอดที่เพิ่งขาย
- แยกข้อมูลออฟไลน์ตามบัญชี/ธุรกิจ/สาขา/พนักงาน คงบิลพักและบิลรอซิงก์รุ่นเดิมไว้เพื่อให้ตรวจยืนยัน ไม่เดาสาขาหรือผู้ขายแล้วส่งอัตโนมัติ
