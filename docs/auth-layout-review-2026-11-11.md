# ตรวจและแก้ layout หน้าสมัคร/เข้าสู่ระบบ — 11 พฤศจิกายน 2026

## ปัญหาที่แก้

- ย้ายลิงก์หน้าหลักไปแถวเดียวกับโลโก้ ลดแถวย้อนกลับที่กินพื้นที่บนมือถือ
- จัดลำดับหัวเรื่อง → ฟอร์มอีเมล → ปุ่มสมัคร/เข้าสู่ระบบ → Google → ลิงก์สลับหน้า Google ที่ยังไม่พร้อมไม่ดันฟอร์มหลักลง
- แยกข้อความทดลองใช้และไม่ใช้บัตรเครดิตเป็นวลีที่ครบความหมาย ปรับข้อความแพ็กเกจให้สั้นและอ่านรู้เรื่อง กำหนดการตัดบรรทัดเฉพาะแต่ละส่วน ไม่ใช้ `nowrap` กับทุกข้อความ
- ย้ายเงื่อนไขรหัสผ่านไว้ข้าง label เพิ่มปุ่มเปิด/ซ่อนในช่องรหัสผ่านแต่ละช่อง ขนาดกด 46 × 46 px ปุ่มหลัก/ช่องกรอกสูง 48 px และ input 16 px
- แก้การกดสมัครครั้งแรกไม่ติดเมื่อรหัสผ่านไม่ตรงกัน: เดิม `onBlur` เพิ่มข้อความผิดพลาดแล้วเลื่อนปุ่มระหว่าง pointer down/up ใช้แถวคำแนะนำ/ข้อความผิดพลาดความสูงคงที่ จึงเตือนและโฟกัสช่องยืนยันได้ตั้งแต่การกดครั้งแรก
- มือถือใช้หน้าฟอร์มสีขาวและขอบ 20 px; tablet/desktop ใช้การ์ดที่มีขนาดจำกัดบนพื้นครีม ไม่ขยาย input เต็มจอ tablet
- ปรับเฉพาะ AuthForm/AuthLayout และ CSS ที่จำกัดขอบเขตหน้า account ไม่เปลี่ยน schema ราคา ฟีเจอร์สิทธิ์ หรือข้อมูลร้าน

## การใช้ skill

ใช้ UI/UX Pro Max ค้น `orphan heading line balance` ได้แนวทาง typography ที่ตรงปัญหา: จัดความกว้างหัวเรื่อง ใช้ balance เป็น enhancement และตรวจข้อความจริงแต่ละภาษา ไม่บังคับตัดด้วย `<br>` หรือ nonbreaking space ทั้งย่อหน้า การค้น stack Next.js สองครั้งไม่ให้คำแนะนำ CSS ที่ตรงประเด็น จึงไม่ได้อ้างผลนั้นเป็นหลักในการแก้ layout ใช้ CSS ปัจจุบันของโปรเจกต์และตรวจผลจริงผ่าน Playwright

## หลักฐานตรวจหน้าจอ

ตรวจ Chromium 90 กรณี: 8 เส้นทาง × 9 ขนาด และสถานะ validation/reveal/server error เพิ่ม 18 กรณี

- ขนาด: 320×740, 360×800, 375×812, 390×844, 430×932, 768×1024, 1024×768, 844×390, 1440×900
- เส้นทาง: register ปกติ/เลือกแพ็กเกจ, login ปกติ/GoogleLinkRequired/GoogleLinkInvalid, forgot-password, reset-password และ verify-email
- ตรวจ overflow ของ document/controls, การขึ้นบรรทัดของหัวเรื่องและวลีสั้น, เป้ากด, เปิด/ซ่อนรหัสผ่านแยกช่อง, การแสดงข้อผิดพลาด และการโฟกัสช่องยืนยันตั้งแต่คลิกแรก
- ทดสอบ server error ในฟอร์มด้วย HTTP 409 ที่ดักเฉพาะใน browser ไม่สร้างบัญชีหรือส่งอีเมลจริงสำหรับการตรวจภาพ
- ภาพก่อน/หลังและผลตรวจ: `output/auth-layout/` รวม `responsive.json`, `review.js`, ภาพ register/login ที่ mobile/tablet/desktop และสถานะผิดพลาด/เลือกแพ็กเกจ ตรวจภาพด้วยตาแล้ว
- `npm run build` และชุดทดสอบระบบ 75/75 ผ่าน ข้อมูลเดิมใน snapshot หลังทดสอบตรงก่อนเริ่มแก้ราคา/Google

การตรวจขนาดจอเป็น Chromium viewport emulation ไม่ใช่การทดสอบ Safari/อุปกรณ์จริง และ Google OAuth ยังปิดไว้จนกว่าจะมี credentials ตามสถานะเดิม
