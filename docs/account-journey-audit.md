# ตรวจเส้นทางบัญชีและเริ่มใช้งาน — 6 พฤศจิกายน 2026

## ขอบเขตและหลักฐาน

ตรวจใน `pos.buzlike` ตั้งแต่หน้าแรก/ราคา สมัครและ login ตั้งร้าน เข้าใช้งาน เลือกร้าน สิทธิ์ตามบทบาท session และ logout รวมถึงเปิดเมนูหลังบ้าน 10 หน้าเพื่อหา error และปัญหา responsive งานนี้ไม่ใช่การรับรองว่าฟีเจอร์ SaaS v2 หรือทุกการแก้ข้อมูลในหลังบ้านเสร็จครบแล้ว

โค้ดที่อ่านครอบคลุมหน้าทางเข้า, Auth.js callbacks, middleware, register/onboarding API, account/staff cookies, tenant authorization, app shell, pricing, dashboard และชุดทดสอบเดิม ใช้บัญชีทดสอบแยกบน `127.0.0.1:3100` ผ่านแท็บเบราว์เซอร์ด้านขวา ส่วนบัญชีผู้ใช้บน `localhost:3100` ยังคงเดิม ไม่สร้างร้านหรือบิลในบัญชีผู้ใช้

## ข้อบกพร่องที่แก้

| จุดที่พบ | พฤติกรรมหลังแก้ |
|---|---|
| หน้าแรก/ราคาไม่อ่านสถานะบัญชี ทุกคนเห็น login/register | ใช้สถานะบัญชีจาก server ร่วมกันทั้งเมนู hero การ์ดราคา CTA ท้ายหน้า และ footer |
| บัญชีล็อกอินแล้วแต่ยังไม่มีร้านไม่มีทางกลับเข้าตั้งร้านที่ชัด | แสดง “ตั้งร้านต่อ” และมี logout ในหน้าตั้งร้าน |
| เปิด `/login` ได้แม้ล็อกอินอยู่ | login และ register ส่งต่อไป `/start` ไม่แสดงฟอร์มซ้ำ |
| `/start` เลือกร้านแรกและส่งทุกบทบาทไป POS | ร้านเดียวเปิดผ่าน store entry; หลายร้านให้เลือก; PIN role KITCHEN/WAITER/CASHIER ไปหน้าที่มีสิทธิ์ |
| ร้านว่างกลับมาแล้วตกอยู่หน้าขายโดยไม่มีสินค้า | OWNER/MANAGER กลับไปหน้าสินค้าหากยังไม่มีสินค้า |
| เข้า onboarding ซ้ำแล้วสร้างร้านใหม่โดยไม่ตั้งใจ | ผู้มีร้านกลับร้านเดิม; สร้างเพิ่มผ่านลิงก์ชัดเจน `?new=1` ภายใต้เพดานเดิม 5 ร้าน |
| ไม่สามารถเข้าหน้าเลือกร้านจากในร้าน | กดชื่อร้านใน header เพื่อเลือกร้าน/สร้างเพิ่มได้ |
| โลโก้ในร้านส่งทุกบทบาทไป dashboard ที่บางคนไม่มีสิทธิ์ | ใช้ store entry ที่ตรวจสิทธิ์ตามบทบาท |
| หน้า denied/ร้านถูกระงับชวนไป billing และวนกลับ store start | แสดงทางออกไปหน้าเลือกร้าน; billing แสดงเฉพาะ OWNER เมื่อเป็น feature gate; ไม่พบร้านตอบ 404 |
| พนักงานเห็น upsell และเมนูที่แพ็กเกจไม่อนุญาต | ลิงก์จัดการแพ็กเกจเฉพาะ OWNER และซ่อนเมนู feature ที่ไม่ได้เปิด |
| Logout ทิ้ง cookie สลับพนักงานไว้ | ล้าง account session และ `pos-staff-*`; ล้าง catalog/cache ของบัญชี โดยรักษาบิลรอซิงก์และบิลพัก |
| Logout อาจพาออกไปคนละ hostname ตาม AUTH_URL | ออกจากระบบแบบไม่ใช้ redirect จาก provider แล้วกลับ `/` บน origin ปัจจุบัน |
| session หาย/หมดอายุหรือบัญชีถูกลบแล้ว UI ค้าง และ browser back แสดงฟอร์มเก่า | ตรวจ session เมื่อ mount/เปลี่ยนหน้า/ย้อนกลับ/กลับเข้าแท็บ/focus/pageshow; ผู้ล็อกอินออกจากฟอร์ม login/register และผู้ไม่มี session ออกจาก protected page; API 401 หยุดแสดงร้านและมีปุ่ม login; token ของบัญชีที่ลบใช้ต่อไม่ได้ |
| สมัครสำเร็จ/เข้าสู่ระบบล้มเหลวหรือกดซ้ำมีทางเดินไม่ชัด | กัน submit ซ้ำ ตรวจผล signIn ก่อนเดินหน้า ใช้ `/start` จุดเดียว และแจ้งอีเมลซ้ำโดยไม่พูดถึงรหัสร้าน/SKU |
| หน้าแรกอ้างว่ามีสินค้าตัวอย่างและต้องตั้งค่ารับเงินก่อน | ข้อความตรงกับร้านว่าง เพิ่มสินค้า/ราคาเอง และตั้งพร้อมเพย์/ภาษีภายหลัง |
| Tablet 768px บีบ hero เป็นสองคอลัมน์จนหัวข้อแตกหลายบรรทัด | เพิ่มช่วง layout สำหรับ tablet แนวตั้ง และจัดเมนูให้พอดี |
| ปุ่มเบียดหัวข้อหลังบ้านบนมือถือ และปุ่ม outline มีขอบซ้อน | หัวข้อและแถวปุ่มแยกบรรทัดบนมือถือ แก้ outline ซ้อนและคง focus-visible สำหรับ keyboard |
| กราฟ dashboard ดันหน้ากว้างกว่ามือถือ | จำกัด grid/panel และเลื่อนเฉพาะกราฟภายใน region ที่ใช้ keyboard ได้ |
| Dashboard เปิด CSV แม้ trial ไม่ได้สิทธิ์ และโหลดรายงานล้มเหลวเงียบ | ปุ่มตรงกับสิทธิ์ และแสดงข้อผิดพลาดจากการโหลดรายงาน |

## การทดสอบอัตโนมัติ

Production build รวม type validation ผ่าน; `npm test` ผ่าน 25 รายการ ชุดใหม่ `tests/account-journey.test.ts` มี 6 กลุ่มสถานการณ์:

1. ผู้เยี่ยมชม, session หมดอายุ, protected entry
2. สมัครผ่าน API แล้วเข้าสู่ระบบผ่าน credentials/CSRF จริง: รหัสผิดและรหัสถูก
3. บัญชีใหม่: หน้าแรก/ราคา/ทุก CTA ไม่มีลิงก์สมัครหรือล็อกอินซ้ำ และกลับมาตั้งร้านได้
4. ร้านว่าง/มีสินค้า, สร้างร้านเพิ่มโดยตั้งใจ, หลายร้าน, สมาชิกถูกปิดใช้งาน
5. PIN operator roles, ไม่มีสิทธิ์, ร้านถูกระงับ, ร้านไม่มีอยู่
6. ผู้ดูแลแพลตฟอร์ม, บัญชีถูกลบ, signout และ cookie พนักงาน, protected entry หลัง logout

ชุดเดิมยังทดสอบการยืนยัน password/PIN, ร้านใหม่ว่าง, เพิ่มสินค้าจริง, isolation ข้ามร้าน, กะ/ขายเงินสด/สต็อก/คืนเงิน, QR, feature gates, checkout authorization, billing activation และแบบ DB v2 ใน schema ชั่วคราว

## การตรวจผ่านเบราว์เซอร์

- ใช้แท็บด้านขวาแท็บเดิม ไม่มีหน้าต่าง browser ภายนอก
- เดินจริงด้วยบัญชีทดสอบสองร้าน: guest → login → picker → ร้านว่าง → เพิ่มหมวดหมู่ → เพิ่มสินค้าราคา 45 บาท/สต็อก 10 → เปิดกะ → ขายเงินสดรับ 50/ทอน 5 → ใบเสร็จ
- บัญชีที่ล็อกอินเข้า `/login` และ `/register` ถูกส่งกลับ picker จริง
- เปิดภาพรวม รายการขาย สินค้า คลังวัตถุดิบ ผังโต๊ะ จอครัว กะ พนักงาน ตั้งค่า แพ็กเกจ ทั้ง 390/768/1440px: ตรวจชื่อหน้า error และ document overflow ไม่ได้อ้างว่าได้ทดสอบทุก mutation ของทั้ง 10 หน้า
- รอบแรกพบ dashboard ล้นที่ 390px และแก้แล้ว ตรวจ dashboard ซ้ำที่ 320/390/768/1024/1440px ผ่าน; CSV ของ trial ไม่เปิดใช้งาน
- หน้าแรกที่ล็อกอินตรวจ 13 ขนาด 320–1440px ไม่มี login/register actions หรือเมนูชนกัน; ตรวจภาพ tablet แล้วแก้ composition เพิ่ม
- รอบสุดท้ายหน้าแรก 13/13, ข้อมูลร้าน 5/5 และ PIN 5/5 ผ่าน ไม่มี document overflow; ปุ่ม PIN สูงอย่างน้อย 56px
- Logout ผ่านหน้าจอจริงกลับ origin เดิมในสถานะ guest; กดย้อนกลับแล้วไม่มี shell/picker ของร้านทดสอบค้าง กลับ localhost โดยตรงยืนยันว่าบัญชีเดิมยังอยู่และเห็น “ตั้งร้านต่อ”
- หลักฐานอยู่ใน `output/playwright/account-journey/`: JSON geometry, หน้าเลือกร้าน, ร้านว่าง, ใบเสร็จ และภาพหน้าที่แก้แล้ว

## งานที่ยังไม่อ้างว่าเสร็จ

- Provider payment E2E, automatic recurring/reconciliation, SMTP/email verification/reset/invite และ Google OAuth ต้องทำ/ตั้งค่าตามแบบ v2 ก่อนเปิดใช้งานจริง
- การคงแพ็กเกจที่เลือกผ่าน signup/checkout, server idempotency ของการสร้างร้าน และ persistent onboarding draft ยังเป็นงานในแผน UX เดิม
- Schema v2 และสิทธิ์หลายสาขาฉบับใหม่ยังเป็น blueprint ไม่ใช่ migration ที่เปิดใช้ครบแล้ว
- Browser viewport checks แยกจาก hardware iOS/Android, เครื่องพิมพ์จริง, load test และ production deployment

บัญชี/ร้าน/บิลที่สร้างสำหรับ browser audit ถูกลบหลังตรวจเสร็จด้วย `scripts/qa-account-journey.mts cleanup` ซึ่งตรวจ ID เจ้าของและอีเมล fixture ก่อนทำงาน ไฟล์หลักฐานเป็นข้อมูลทดสอบ ไม่ใช่ข้อมูลธุรกิจของผู้ใช้; ไม่เปลี่ยนราคาแพ็กเกจหรือรีเซ็ตร้านเดิม
