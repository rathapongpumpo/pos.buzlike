# เฟส 1 — ข้อมูลและสิทธิ์หลายสาขา

วันที่ 8 พฤศจิกายน 2026 · **ผ่านใน local ตามขอบเขตเฟส 1** · ยังไม่ใช่การอนุมัติ go-live

## ผลส่งมอบ

- เพิ่ม `StaffBranchAccess`, `BranchProduct` และ `ProductStockMovement` พร้อม composite foreign keys ที่ผูก tenant/branch/product/order และข้อห้ามยอดติดลบ
- เจ้าของเข้าทุกสาขา บัญชีและผู้ใช้ PIN ต้องมีสิทธิ์ตรงกัน พนักงานไม่ได้สิทธิ์สาขาใหม่อัตโนมัติ; แก้สิทธิ์สาขาโดยคง PIN เดิมได้
- ราคา เปิดขาย และสต็อกรายชิ้นแยกสาขา แคตตาล็อกชื่อ/SKU/หมวดหมู่/สูตรใช้ร่วมกัน; ปรับยอดมีเหตุผลและ version ป้องกันเขียนทับการขายล่าสุด
- ขาย/คืน/รายงาน/เงินในกะ/QR/realtime ใช้สาขาที่ตรวจสิทธิ์แล้ว คืนสินค้าเข้าสาขาของบิลเดิมครั้งเดียว และปิด SSE เมื่อถูกถอนสิทธิ์
- บิลซ้ำคืนบิลเดิมโดยไม่ตัดซ้ำ; การขายพร้อมกันใช้ transaction พร้อม retry ที่หน่วงเพื่อไม่ชนซ้ำ
- cache, บิลพัก, คิว offline และจอลูกค้าแยกบัญชี/ธุรกิจ/สาขา/ผู้ปฏิบัติงาน; terminal ID ยังคงเป็นเครื่องเดิม ไม่กินโควตาใหม่เมื่อสลับสาขา
- คงบิลพักและคิวรุ่นเก่าไว้ ต้องตรวจและยืนยันก่อนใช้ ไม่เดาสาขาหรือผู้ขาย; ไม่ล้าง IndexedDB ของลูกค้า
- export/import รวมราคา สต็อก grants และ ledger ใหม่ พร้อมอ่านไฟล์รุ่นเดิมได้

Migration ที่ใช้: `prisma/migrations/20261108060000_branch_isolation/migration.sql` เป็นการเพิ่มโครงสร้างใน schema ปัจจุบัน ไม่ใช่การย้ายครบทุกตารางของ blueprint v2

## การตรวจที่ผ่าน

- Prisma validate / migrate deploy / generate, TypeScript และ production build ผ่าน
- `npm test`: **32 ผ่าน, 0 ล้มเหลว, 0 ข้าม** — [ผลรันทดสอบ](evidence/phase1-tests.txt)
- ตรวจ tenant/branch authorization, ห้ามยกระดับผ่าน PIN, ราคา/สต็อกต่อสาขา, cash/report isolation, บิลซ้ำพร้อมกัน 4 คำขอ, stock version เก่า, ผู้ขายไม่ตรงคิว, คืนผิดสาขา/คืนซ้ำ, 8 คำขอขายแข่งยอด 2 ชิ้น, ถอนสิทธิ์ระหว่างเปิด SSE, FK และยอดติดลบ
- export → import ไป schema ว่าง คืน grants/ราคา/ยอดของสองสาขา และ refund ไม่กระทบอีกสาขา
- service worker ทดสอบด้วย VM/fake network/cache: ไม่บันทึกหรือใช้หน้าไม่มี scope, ไม่คืน cache ข้ามสาขาหรือผู้ปฏิบัติงาน; คิวตรวจ branch/operator ก่อน replay
- Browser ด้านขวาของ Codex: มือถือ 390×844, tablet แนวตั้ง 820×1180 และแนวนอน 1180×820 ไม่มี document overflow; ตัวเลือกสาขาและแถวเลือกสิทธิ์สูง 48px
- Browser จริงสลับราคา/ยอด A=45/10 และ B=65/6, บันทึก grant ด้วย tablet แล้วแก้กลับด้วยมือถือโดยไม่เปลี่ยน PIN, ห้ามสลับสาขาขณะมีตะกร้า, พักบิล A แล้ว B ว่าง กลับ A เรียกคืนได้ 45 บาท

ระหว่างตรวจพบ transaction conflict เมื่อส่งขายซ้ำพร้อมกัน จึงเพิ่ม backoff และเพดาน retry แล้วรันชุดทดสอบใหม่จนผ่าน ไม่อ้างผลจากรอบที่ล้มเหลว

## ข้อจำกัดและเฟสถัดไป

- Browser รอบนี้ทดสอบบิลพักและการสลับสาขาขณะ online; การตัดเน็ตจริง/reload แล้ว sync ของโครงสร้างใหม่ยังต้องตรวจในเฟส 5 หลักฐาน offline เดิมไม่ถือเป็นผลทดสอบโค้ดใหม่
- มี cold backup แต่ยังไม่ได้ซ้อม restore backup ก้อนนี้; ทำในเฟส 4
- การขายพร้อมกันที่ตรวจเป็น local correctness test ไม่ใช่ capacity/load test หรือรับรองหลาย instance
- ยังไม่มีหลักฐานจากเครื่องพิมพ์/อุปกรณ์จริง, payment provider, SMTP หรือ production
- โอนคลัง ซื้อเข้า โปรโมชั่น/CRM ขั้นสูง และ v2 ส่วนอื่นไม่ได้รวมในเฟสนี้ ต้องไม่โฆษณาว่าพร้อมจากผลเฟส 1
